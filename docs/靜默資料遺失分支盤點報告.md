## 總結

### 已有告警覆蓋的路徑
1. ✅ twinkle 查詢失敗 → logger.warning
2. ✅ twinkle hit 缺 title → logger.warning  
3. ✅ web search 失敗 → logger.warning
4. ✅ written.get(q) 為 None → logger.warning + 【待補證】佔位
5. ✅ CLI 單檔失敗 → stderr 錯誤訊息
6. ✅ __main__.py 無 twinkle token → 警告訊息

### 缺口分析

#### 高優先級缺口 (可能導致靜默資料遺失)
1. **parse_note 空檔案無告警** - 可能產生空 Document 但無告警
2. **detect_domain 降級無告警** - LLM 格式錯誤時靜默降級為 "other"
3. **generate_questions 格式錯誤無告警** - JSON/陣列格式時靜默返回 []
4. **law_search 關鍵詞抽取失敗無告警** - 無法找到法條來源但無告警
5. **web fetch 失敗無告警** - 單頁抓取失敗靜默跳過
6. **web 全文過短無告警** - 視為抓取失敗靜默跳過
7. **web 分級失敗無告警** - 分級例外時靜默跳過
8. **assemble_correction 來源缺失無告警** - used_source_ids 找不到對應 Source 時靜默跳過
9. **_verify_law_citations 法條未找到無告警** - 降級為 pending_evidence 但無告警

#### 中優先級缺口 (影響較小)
1. **[^n] 標記越界無告警** - 靜默移除越界標記
2. **detect_gaps 各種格式錯誤無告警** - 雖有保守降級但缺乏記錄

### 建議修復優先順序
1. 🔴 高風險：parse_note 空檔告警、law_search 關鍵詞抽取失敗告警
2. 🟡 中風險：detect_domain/generate_questions 降級告警、web 各種失敗告警
3. 🟢 低風險：[^n] 越界告警、assemble_correction 來源缺失告警

## 驗證方法
建議針對上述缺口新增回歸測試，確保：
1. 空檔案輸入時有適當告警
2. LLM 格式錯誤時有降級告警
3. 外部服務失敗時有明確記錄
4. 來源缺失時有追蹤能力
