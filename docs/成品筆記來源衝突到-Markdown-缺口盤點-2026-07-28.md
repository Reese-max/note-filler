# 成品筆記來源衝突到 Markdown 缺口盤點

## 結論

最後一段缺口是 `three_part_annotation.source_comparison`：它已由內部 `Source` 資料組成、已寫入 JSON，但 `to_markdown()` 沒有渲染它。衝突告警 `conflict_note`、待補證狀態與來源差異／適用條件／結論則都已抵達 Markdown，毋須改動資料模型或管線。

## 資料流與實際落點

| 階段 | 資料 | 實際行為 |
| --- | --- | --- |
| 驗證模型 | `Validation.conflict`、`Validation.conflict_note`（`src/note_filler/verify.py:13-19`） | `cross_validate()` 偵測衝突但不選邊。 |
| 組裝模型 | `Segment.conflict_note`（`src/note_filler/correction.py:168-201`） | `assemble_correction()` 僅在 `conflict=True` 時轉送訊息（`src/note_filler/correction.py:324-328`）。`conflict` 布林值本身不獨立保存；目前由非空 `conflict_note` 表達衝突，並非 Markdown 的最後一段缺口。 |
| 共用匯出註解 | `source_comparison`（`src/note_filler/export.py:223-240`、`349-369`） | `_source_comparison_rows()` 建立逐來源列，`_three_part_annotation()` 將其放入註解。 |
| JSON 序列化 | `three_part_annotation`（`src/note_filler/export.py:466-493`） | `to_json()` 完整輸出 `source_comparison`。 |
| 最終 Markdown | `to_markdown()`（`src/note_filler/export.py:552-614`） | 已輸出 `conflict_note`、`discrepancy_notes`、`usage_conditions`、`conclusion`，但未讀取或輸出 `annotation["source_comparison"]`。 |

## 尚未輸出的欄位與函式

`source_comparison` 的逐列關聯在 Markdown 完全未輸出，包含：

- `id`
- `level`
- `title`
- `url`
- `doc_date`
- `distance`
- `content_summary`

其中部分值可能在其他 Markdown 區塊分散出現（例如參考來源或適用條件），但沒有同一筆來源的比較列；`content_summary` 也沒有明確的 Markdown 輸出。缺口函式鏈為：`_source_comparison_rows()` 的回傳值已交給 `_three_part_annotation()`，而 `to_markdown()` 只渲染後三個註解欄位，未渲染 `source_comparison`。

## 需要修改的序列化／渲染檔案

- `src/note_filler/export.py`：在 `to_markdown()` 將 `annotation["source_comparison"]` 渲染為與補充段綁定的來源比較區塊；不需修改資料模型、檢索、驗證或管線檔案。
